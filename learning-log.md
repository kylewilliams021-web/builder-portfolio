# What I'm learning

Concepts I've picked up by building, in my words, with where I met them. Newest first. Each one comes from
a real session, recorded in that project's build log.

| Date       | Concept                    | What it means                                                                                                                                                   | Where                      |
| ---------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 2026-10-12 | Distributional convergence | Why AI output looks the same: a model picks the most common choice; ban one default and it falls back to the next (dark + neon green, cream + big italic serif) | Research: not-AI checklist |
| 2026-10-12 | Go-live criteria           | The bar a product must clear before real customers use it (also called launch or exit criteria)                                                                 | Interview: SouthBay420     |
| 2026-10-12 | Demand validation          | Testing whether anyone wants something before investing in it (e.g. would stores use it if open-sourced?)                                                       | Interview: SouthBay420     |
| 2026-10-11 | Build vs buy               | Weighing control and fit (build) against cost, time and upkeep (buy): a classic product call                                                                    | Interview: SouthBay420     |
| 2026-10-11 | North Star metric          | The one number that best captures the value a product delivers; if it rises, the product works                                                                  | Interview: SouthBay420     |
| 2026-10-11 | Positioning to an audience | The same work framed for who's listening: a sales manager and a product leader hear different things                                                            | Dutchie application        |
| 2026-10-11 | Build log vs changelog     | The changelog says what changed; the build log says how and why — the part that shows judgment                                                                  | Documentation system       |
| 2026-10-11 | Decision record            | A short note of a choice, its options and its reasoning, never rewritten later                                                                                  | Documentation system       |
| 2026-10-11 | Jobs to be done            | Describe what someone is trying to get done ("when…, I want…, so…"), not features                                                                               | SouthBay420 product doc    |
| 2026-10-11 | Harness                    | Everything around an AI model that lets it act safely: agent = model + harness                                                                                  | SouthBay420 AI harness     |
| 2026-10-11 | Rules vs hooks             | A rule is advice the AI may forget; a hook is code that can refuse the action                                                                                   | SouthBay420 AI harness     |
| 2026-10-11 | Checks outside the agent   | Tests run by the system, not the AI, so it isn't grading its own homework                                                                                       | SouthBay420 AI harness     |
| 2026-10-11 | Flaky test                 | A test that passes or fails at random; it hides real bugs and trains people to ignore failures                                                                  | SouthBay420 AI harness     |
